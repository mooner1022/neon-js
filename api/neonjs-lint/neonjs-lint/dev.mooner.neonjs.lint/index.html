LintResult
Link copied to clipboard
class LintResult(val diagnostics: List<Diagnostic>, val syntaxErrorCount: Int, val truncated: Boolean, val cancelled: Boolean)

The diagnostics of a source, ordered by offset: its syntax errors and its rules' findings. syntaxErrorCount: the syntax errors found. The parse stops at the diagnostic limit, so when truncated it counts those found up to it, and the source may have more. truncated: the limit left some out. cancelled: the check was cancelled before its end; the diagnostics are then those found before (possibly none).

interface LintRule

A lint rule: reads the tree and the scope analysis, and reports what it finds. The built-in ones are BuiltinRules; a host adds its own through LintOptions.extraRules. (What it reads is marked LintTreeApi.)

LintTreeApi

@RequiresOptIn(message = "The tree a lint rule reads is NeonJS's parser's: not a stable API.")

annotation class LintTreeApi

Marks what a host's rules see: the parser's tree and the scope analysis's results, which are not a stable API (they change with the engine). A host rule is built against one version of NeonJS.

NeonLint

object NeonLint

The linter for NeonJS's JavaScript: the engine's own parser in its recovery mode (every syntax error, the first the engine's, and the code after them still checked), the compiler's scope analysis, and rules for mistakes that are valid code (rules). No style rules.
