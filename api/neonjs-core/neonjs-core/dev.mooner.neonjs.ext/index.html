ConsoleBuiltins

object ConsoleBuiltins

The console namespace object. All formatting is done by Inspector, which never calls back into guest code, so logging an object cannot trigger getters, proxies or toString overrides, unless an engine module gives the realm a Formatter of its own (setFormatter; neonjs-node's formats as Node's console does).

Inspector
Link copied to clipboard
object Inspector

Node-like value formatting for console output and the REPL. Never invokes user code (getters, toString, proxies are not triggered), so it is safe to use on untrusted values.

WebGlobals

object WebGlobals

Opt-in web platform globals that embedded scripts commonly expect (not part of ECMAScript): queueMicrotask, setTimeout / setInterval / clearTimeout / clearInterval, structuredClone, DOMException, atob / btoa, UTF-8 TextEncoder / TextDecoder, Event / CustomEvent / EventTarget (Events) and AbortController / AbortSignal (Abort), MessageEvent / CloseEvent / ErrorEvent, performance (Performance) and crypto.getRandomValues / randomUUID (Crypto), Blob / File (Blob), FormData (FormData), Headers (Headers), Request / Response (Fetch) and URL / URLSearchParams (Url). fetch and WebSocket come with a transport (WebNetwork).

WebNetwork
Link copied to clipboard
object WebNetwork

The network under fetch and WebSocket, for engine modules: neonjs-net's NetExtension gives a realm its transports (with its policy) through install; without them the realm has neither global. The web globals do the standards' part on the context's thread (requests and responses, redirects, header guards, aborts, ready states and events); a transport moves bytes, decides what may be reached, and calls back from any thread.
