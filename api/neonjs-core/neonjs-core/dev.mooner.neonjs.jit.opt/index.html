class FrameState(val pc: Int, val values: Array<Value>, val site: InlineSite? = null)

The interpreter's state at an exit (Deopt) in the function compiled (site null) or in the body of a call compiled inlined (site): where it resumes, pc, and the values of the registers then the operand stack there (values). class Graph(val code: CodeBlock, val ops: OpTable, val kindSystem: KindSystem, val deadValue: Any?, val dialect: Dialect)

The optimizing tier's intermediate representation (docs/OPTIMIZING_TIER.md, "IR"): a control flow graph of Blocks whose instructions are in SSA form. A Value is defined once: a constant, a parameter, a phi at the start of a block, or an instruction's result.

GraphBuilder
Link copied to clipboard
abstract class GraphBuilder(cb: CodeBlock, g: Graph, stressExits: Boolean, speculate: Boolean)

Builds the Graph of a code block from its bytecode, whatever its language: registers and operand stack slots become SSA values, with a phi at every merge for every one of them, then the phis that merge one value (or only themselves) are replaced by it and those nothing uses are dropped. The language's subclass decodes its bytecode (Body.length, Body.targets, Body.regsRead), builds each instruction (Body.buildOp) and makes the graph's start (entry); the order of the passes after is the core's (build).

class InlineSite(val parent: InlineSite?, val code: CodeBlock, val callPc: Int, val callerState: FrameState, val frame: Array<Value>, val flags: Int = 0)

A call compiled inlined: the callee's code, the call at callPc in its caller (the body of parent, or the function compiled), the caller's state at that call (callerState: its registers and the stack below the call's operands), and what a frame of the callee holds as its language lays it out (frame: JavaScript's closure, this as the call binds it, the arguments, the environment), which an exit inside the body passes to the interpreter, in that order. flags are the language's facts about the call (JavaScript's: a construction).

object Ir

The operations of the IR that every language's graphs have (docs/IR_NEUTRALITY.md): terminators, exception handlers' homes, the records and guards of calls compiled inlined, the stress mode's exits. IrCodegen
Link copied to clipboard
abstract class IrCodegen(g: Graph, mv: MethodVisitor, kinds: Kinds, cw: ClassWriter, className: String) : JvmEmitter

Generates CompiledCode.run for a Graph, whatever its language: every value used gets a JVM local of its kind's representation (KindSystem.rep), blocks become labels, and a phi's inputs are copied into its local at the end of each predecessor (all loaded, then all stored: a parallel copy through the JVM stack). The JVM operand stack is empty at every block boundary. The language's subclass gives each instruction its code (inst) and the tests of branches; exits, on-stack replacement entries, interrupt checks on back edges and the size of the code are the core's.

object IrVerifier

object JsIr

The operations JavaScript's builder makes besides its bytecode's (Op): parameters, TDZ checks, what a call compiled inlined binds (this, the environment, a construction's object and result), and the speculations (number checks, shape-guarded slots, global cells, builtins computed in place). class Kinds(val system: KindSystem)

The kinds of the IR's values (KindSystem): a forward fixpoint in which phis start with no kind and take the join of their inputs' (kinds only rise), and every instruction's result is the one its language's kind system gives for its inputs' kinds. fun interface Resumer

How an exit of the optimizing tier's code continues the activation in its language's interpreter: f, the frame the code runs, at pc with values (its registers, then its operand stack), the calls compiled inlined around the exit in inner (the language's records, innermost first, as its code generator made them).
