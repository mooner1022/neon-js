Deopt

object Deopt

Deoptimization (docs/OPTIMIZING_TIER.md, "Deoptimization"): compiled code leaves an activation to the interpreter in the middle of its function, at an exit, with the interpreter state of every frame live there.

The frame compiled code runs becomes an interpreted frame in place (it keeps its identity, which error objects, frame chains and the agent's top frame hold). A call compiled inlined that is live at the exit becomes a frame of its own: the innermost runs first, its result goes on its caller's operand stack and the caller continues after the CALL; an exception it throws is thrown in the caller at the CALL, through the caller's handlers. A construction (at a NEW) is resumed as one: the frame's new.target is the constructor, and the result is this unless the body returned an object.

fun finishCall(f: Frame)

Completes the call f waits for (Frame.deoptCall) at its CALL at Frame.pc: the callee runs in the interpreter as a frame of its own, then its result is pushed and f is after the CALL, or the exception it threw is f's pending throw at the CALL. f is the agent's top frame.

resume
Link copied to clipboard
@JvmStatic
fun resume(f: Frame, pc: Int, values: Array<Any?>, inner: Deopt.Inlined?): Any?

Continues f, the frame of an activation of compiled code, in the interpreter: at pc with values (registers, then the operand stack), or, with inner, after the CALL at pc (with values below its operands) once the call inner completed. Returns the frame's result; when the code was given f interpreted (on-stack replacement), it returns JitRt.DEOPTED instead and the interpreter that called it continues the frame, so that a loop entering compiled code and leaving it again does not nest interpreters.

tierUp
Link copied to clipboard
@JvmStatic
fun tierUp(f: Frame, pc: Int, values: Array<Any?>): Any?

Continues f, whose code found a later version of its block's code installed at a loop back edge (JitRt.canTierUp), in that version: the frame becomes interpreted at the loop header pc with the registers values, then enters the new code there by on-stack replacement; where that code declines the entry or deoptimizes, the interpreter goes on. Returns the frame's result, or JitRt.DEOPTED when the code was given f interpreted (as resume).
